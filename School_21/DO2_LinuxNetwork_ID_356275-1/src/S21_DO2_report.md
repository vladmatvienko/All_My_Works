## Part 4. Сетевой экран

- **4.1. Содержимое файлов `/etc/firewall.sh` на `ws1` и `ws2`:**
  - На `ws1` запрещающее правило `DROP` для `echo-reply` расположено раньше разрешающего `ACCEPT`.
  - На `ws2` разрешающее правило `ACCEPT` для `echo-reply` расположено раньше запрещающего `DROP`.
  - На обеих машинах разрешены входящие TCP-подключения к портам `22` и `80`.

  ![Правила iptables в файлах /etc/firewall.sh на обеих машинах](Images/Part%204_1.png)

- **Запуск файлов и проверка установленных правил:**

  ![Запуск firewall.sh и вывод iptables -L -v -n на обеих машинах](Images/Part%204_2.png)

- **Разница между стратегиями:**
  - `iptables` проверяет правила сверху вниз и применяет первое совпавшее правило.
  - Если сначала указано `ACCEPT`, пакет будет разрешён, а расположенное ниже правило `DROP` уже не сработает.
  - Если сначала указано `DROP`, пакет будет отброшен, а расположенное ниже правило `ACCEPT` не будет достигнуто.

- **4.2. Проверка работы сетевого экрана с помощью `ping` и `nmap`:**
  - На машине, где правило `DROP` для `echo-reply` расположено раньше `ACCEPT`, ответные ICMP-пакеты блокируются, поэтому удалённый `ping` завершается потерей пакетов.
  - На машине, где правило `ACCEPT` расположено раньше `DROP`, ICMP-ответ разрешается и `ping` выполняется успешно.

  ![Успешная проверка ping для машины с разрешающим правилом ACCEPT перед DROP](Images/Part%204_3.png)

  - Сканирование TCP-портов утилитой `nmap` подтверждает, что узел работает и сетевые службы доступны независимо от обработки ICMP-пакетов.

  ![Результат сканирования узла утилитой nmap и обнаруженные открытые TCP-порты](Images/Part%204_4.png)

- **5.5. Построение маршрута с помощью `traceroute`:**
  - Полученный путь: `ws11 -> r1 (10.10.0.1) -> r2 (10.100.0.12) -> ws21 (10.20.0.10)`.

    ![Маршрут от ws11 до ws21, построенный traceroute](Images/Part%205_27.png)

  - Дамп трафика на `r1`:

    ![Перехват пакетов traceroute на r1 с помощью tcpdump](Images/Part%205_28.png)

  - **Принцип работы `traceroute`:** утилита отправляет пакеты с последовательно увеличивающимся значением TTL. Когда TTL становится равен нулю на очередном маршрутизаторе, он отбрасывает пакет и возвращает сообщение ICMP `Time Exceeded`. По адресам отправителей этих сообщений формируется список промежуточных маршрутизаторов. Когда UDP-пакет достигает конечной машины, она отвечает ICMP `Port Unreachable`, что означает завершение построения маршрута.

- **Проверка SNAT по TCP:**
  - С `ws22` выполнено подключение к Apache на `r1` по адресу `10.100.0.11`, порт `80`.
  - Получение HTML-страницы Apache подтверждает прохождение TCP-соединения через SNAT.
  - Команды и ожидаемый результат проверки:

    ```console
    ws22@ws22:~$ telnet 10.100.0.11 80

    ```

  - После строки `Host: r1` вводится пустая строка нажатием `Enter`. Ответ `200 OK` и HTML-код страницы означают, что TCP-соединение установлено успешно.

  ![HTML-ответ Apache на ws22 при проверке SNAT](Images/Part%207_12.png)

- **Проверка DNAT по TCP:**
  - С `r1` выполнено подключение к внешнему адресу `r2` `10.100.0.12`, порт `8080`.
  - На `r2` правило DNAT заменяет адрес назначения на `10.20.0.20:80`, поэтому ответ фактически приходит от Apache на `ws22`.
  - Точный сценарий проверки:

    ```console
    r1@r1:~$ telnet 10.100.0.12 8080
    Trying 10.100.0.12...
    Connected to 10.100.0.12.
    Escape character is '^]'.
    GET / HTTP/1.0
    Host: ws22

    HTTP/1.1 200 OK
    Server: Apache/2.4...
    Content-Type: text/html
    ...
    Connection closed by foreign host.
    ```

  - Ответ `200 OK` и HTML-код страницы подтверждают, что подключение к `10.100.0.12:8080` было перенаправлено на `10.20.0.20:80`.

- **Перезапуск Apache и проверка локального прослушивания:**

  - Команда `ss -ltnp` показывает прослушивание `127.0.0.1:80`.
  - Локальное подключение `telnet 127.0.0.1 80` устанавливается успешно.

  ![Успешный HTTP-ответ Apache при локальном подключении к 127.0.0.1:80](Images/Part%208_3.png)

- **Подготовка SSH-сервера на `ws22`:**
  - Установлены `openssh-server` и `openssh-client`.
  - Служба SSH включена и запущена.
  - Порт `22` прослушивается на IPv4 и IPv6.

  ![Установка OpenSSH и проверка прослушивания порта 22](Images/Part%208_4.png)

- **Local TCP forwarding с `ws21` до `ws22`:**
  - Команда на `ws21`:

    ```bash
    ssh -N -o ExitOnForwardFailure=yes -L 8080:127.0.0.1:80 ws22@10.20.0.20
    ```

  - Локальный порт `8080` на `ws21` перенаправляется через SSH на `127.0.0.1:80` машины `ws22`.

  ![Запуск локального SSH-туннеля на ws21](Images/Part%208_5.png)

  - Проверка выполняется во втором терминале на `ws21`. Первый терминал при этом должен оставаться открытым с работающей командой `ssh -N`.
  - Полный вид проверки Local TCP forwarding:

    ```console
    ws21@ws21:~$ telnet 127.0.0.1 8080
    Trying 127.0.0.1...
    Connected to 127.0.0.1.
    Escape character is '^]'.
    GET / HTTP/1.0
    Host: localhost

    HTTP/1.1 200 OK
    Server: Apache/2.4...
    Content-Type: text/html
    ...
    Connection closed by foreign host.
    ```

  - После строки `Host: localhost` вводится пустая строка. Ответ Apache подтверждает цепочку `ws21:8080 -> SSH-туннель -> ws22:127.0.0.1:80`.

  ![HTML-ответ Apache на ws21 через Local TCP forwarding](Images/Part%208_6.png)

- **Remote TCP forwarding с `ws11` до `ws22`:**
  - Команда выполняется на `ws22`, чтобы открыть порт `8081` на `ws11` и перенаправить его на локальный Apache `ws22`:

    ```bash
    ssh -N -o ExitOnForwardFailure=yes -R 8081:127.0.0.1:80 ws11@10.10.0.2
    ```

  ![Запуск обратного SSH-туннеля с ws22 на ws11](Images/Part%208_8.png)

  - Проверка выполняется во втором терминале на `ws11`. Терминал `ws22` с командой `ssh -N -R` должен оставаться открытым.
  - Полный вид проверки Remote TCP forwarding:

    ```console
    ws11@ws11:~$ telnet 127.0.0.1 8081
    Trying 127.0.0.1...
    Connected to 127.0.0.1.
    Escape character is '^]'.
    GET / HTTP/1.0
    Host: localhost

    HTTP/1.1 200 OK
    Server: Apache/2.4...
    Content-Type: text/html
    ...
    Connection closed by foreign host.
    ```

  - Ответ Apache подтверждает цепочку `ws11:8081 -> Remote SSH forwarding -> ws22:127.0.0.1:80`.

  ![HTML-ответ Apache на ws11 через Remote TCP forwarding](Images/Part%208_7.png)
