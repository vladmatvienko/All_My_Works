## Part 3. Настройка сети ОС

- Имя машины было задано в формате `user-1` с помощью команды:

```bash
sudo hostnamectl set-hostname user-1
```

- Текущее имя машины проверялось командой:

```bash
hostnamectl
```

- Часовой пояс был установлен в соответствии с текущим местоположением командой вида:

```bash
sudo timedatectl set-timezone <часовой_пояс>
```

- Корректность часового пояса проверялась командой:

```bash
timedatectl
```

- Сетевые интерфейсы были выведены командой:

```bash
ip link show
```

- Интерфейс `lo` присутствует, потому что это **loopback-интерфейс**. Он используется системой для обращения к самой себе. Обычно ему соответствует адрес `127.0.0.1`. Через него локальные процессы могут взаимодействовать друг с другом без выхода во внешнюю сеть.
- IP-адрес устройства, полученный от DHCP-сервера, был проверен командами:

```bash
ip a
hostname -I
```

- **DHCP** расшифровывается как **Dynamic Host Configuration Protocol**. Это протокол динамической настройки узла, который автоматически выдаёт устройству IP-адрес, маску сети, шлюз и DNS-серверы.
- Внутренний IP-адрес шлюза, то есть адрес по умолчанию `gw`, был определён командой:

```bash
ip route
```

- Внешний IP-адрес шлюза был определён с помощью внешнего сетевого запроса командой вида:

```bash
curl ifconfig.me
```

- Статические настройки сети были заданы через конфигурацию Netplan в файле `/etc/netplan/*.yaml`.
- Для настройки статического IP, шлюза и DNS использовались параметры:
  - `dhcp4: no` - отключение получения IPv4-адреса через DHCP;
  - `addresses` - статический IP-адрес машины;
  - `routes` - маршрут по умолчанию через шлюз;
  - `nameservers` - DNS-серверы, например `1.1.1.1` и `8.8.8.8`.
- После изменения конфигурации сеть была применена командой:

```bash
sudo netplan apply
```

- После перезагрузки виртуальной машины статические настройки IP, шлюза и DNS были проверены повторно.
- Доступность удалённых хостов была проверена командами:

```bash
ping -c 4 1.1.1.1
ping -c 4 ya.ru
```

- В выводе ping зафиксировано `0% packet loss`, что подтверждает корректную сетевую настройку.

## Part 8. Установка и базовая настройка сервиса SSHD

- Была установлена служба SSHD:

```bash
sudo apt install openssh-server -y
```

- Служба была добавлена в автозапуск:

```bash
sudo systemctl enable ssh
```

- Служба была запущена:

```bash
sudo systemctl start ssh
```

- Конфигурационный файл SSHD был открыт для редактирования:

```bash
sudo nano /etc/ssh/sshd_config
```

- В конфигурации был задан порт `2022`:

```text
Port 2022
AddressFamily inet
ListenAddress 0.0.0.0
```

- После изменения конфигурации были выполнены команды:

```bash
sudo systemctl daemon-reload
sudo systemctl restart ssh.socket
sudo systemctl restart ssh
```

- Наличие процесса `sshd` было проверено командой:

```bash
ps aux | grep [s]shd
```

- Значение команды и ключей:
  - `ps` - выводит информацию о процессах;
  - `a` - показывает процессы всех пользователей;
  - `u` - выводит процессы в пользовательском формате с владельцем, CPU, памятью и временем;
  - `x` - показывает процессы без управляющего терминала, что важно для служб-демонов;
  - `grep [s]shd` - фильтрует вывод по процессу `sshd`, не добавляя сам `grep` как лишнюю строку.
- После перезагрузки системы было проверено, что SSHD слушает порт `2022`:

```bash
netstat -tan
```

- Значение ключей `-tan`:
  - `-t` - показывает TCP-соединения;
  - `-a` - показывает все соединения и слушающие порты;
  - `-n` - выводит адреса и порты в числовом виде.
- Значение столбцов `netstat`:
  - `Proto` - протокол соединения;
  - `Recv-Q` - очередь полученных, но ещё не обработанных данных;
  - `Send-Q` - очередь данных на отправку;
  - `Local Address` - локальный адрес и порт;
  - `Foreign Address` - удалённый адрес и порт;
  - `State` - состояние соединения.
- Адрес `0.0.0.0` означает, что служба слушает указанный порт на всех доступных IPv4-интерфейсах.
- В выводе `netstat -tan` присутствует строка с `0.0.0.0:2022` и состоянием `LISTEN`.

## Part 9. Установка и использование утилит top, htop

- Были установлены и запущены утилиты `top` и `htop`.
- Для установки `htop` использовалась команда:

```bash
sudo apt install htop -y
```

- Утилита `top` была запущена командой:

```bash
top
```

- По выводу `top` были определены следующие показатели:
  - `uptime` - время непрерывной работы системы отображается в первой строке `top` после слова `up`;
  - количество авторизованных пользователей отображается в первой строке `top` перед словом `user` или `users`;
  - средняя загрузка системы отображается в поле `load average`;
  - общее количество процессов отображается в строке `Tasks`;
  - загрузка CPU отображается в строке `%Cpu(s)`;
  - загрузка памяти отображается в строке `MiB Mem`;
  - PID процесса, занимающего больше всего памяти, определяется после сортировки по памяти;
  - PID процесса, занимающего больше всего процессорного времени, определяется после сортировки по времени CPU.
- В `htop` были выполнены сортировки:
  - по `PID`;
  - по `PERCENT_CPU`;
  - по `PERCENT_MEM`;
  - по `TIME`.
- В `htop` был выполнен фильтр по процессу `sshd`.
- В `htop` был выполнен поиск процесса `syslog`.
- В `htop` были добавлены элементы отображения `hostname`, `clock` и `uptime`.

- В `crontab` была добавлена строка:

```cron
*/2 * * * * /usr/bin/uptime
```

- Список текущих заданий был выведен командой:

```bash
crontab -l
```

- Строки о выполнении задания были найдены в системном журнале командой:

```bash
sudo grep CRON /var/log/syslog | grep uptime
```

- В логах были найдены минимум две строки о выполнении команды `uptime` в заданном временном диапазоне.
- Затем все задания из планировщика были удалены командой:

```bash
crontab -r
```

- После удаления список текущих заданий был проверен повторно командой:

```bash
crontab -l
```
